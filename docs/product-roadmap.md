# Hyper 盯盘实施路线图

## 当前实现审阅

基线为服务器实际工作目录的 v1.3.1（`1a58748`）。应用是 Node.js 与 SQLite，自托管静态前端通过同源 API 和 Hyperliquid WebSocket 读数。

| 层 | 已有 | 缺口与风险 |
| --- | --- | --- |
| 账户与交互 | 注册登录、记住会话、钱包分组收藏、跨设备设置、卡片和表格、搜索排序、快看、隐藏金额、五栏底部导航、PWA | 首页缺少合并后的风险状态与账户事件。手机尺寸与锁屏行为需要分别验证 |
| 行情与仓位 | `public/market.js` 订阅所有永续市场仓位，`public/app.js` 定时读取权益和现货。已有强平距离和仓位杠杆显示 | 断线后首页 REST 快照只覆盖默认市场。缺字段或快照变旧时，汇总不能显示为全市场安全 |
| 收益 | `portfolio` 支持今日、近 24 小时、7 天和 30 天。盈亏页从成交、资金费和资金流水分别汇总 | 没有可补拉的持久账本、连续权益快照或完整覆盖标记。截断、重复成交、手续费口径和充值转账可能造成误算 |
| 提醒 | 服务端成交 WebSocket、REST 断线补漏、资金权益阈值、风险合并、降噪、Web Push、消息记录与已读 | 缺少按仓位和账户的分级风险状态，以及数据中断规则。事件目前无结构化的风险等级及仓位链接 |
| 历史 | 动态页和盈亏页查询近期成交，现有归类支持开仓、加减仓、平仓和反手 | 缺未成交订单、订单状态、长期原始记录和完整仓位生命周期。接口历史上限需要显示给用户 |
| 存储和服务 | `profiles`、`accounts`、`alerts`、`alert_reads`、`alert_status`、`transmissions`、`push_devices`、`task_leases` 和成交缓冲；现有行情代理有权重预算和重试退避 | 浏览器页面分别获取行情，现有缓存面向请求而不是数据集。迁移按 SQLite `user_version` 增量执行，后续要保留逐阶段回滚路径 |

## 阶段一　iPhone 概览与风险驾驶舱

- 在 `public/index.html`、`app.js` 和移动端样式中加入账户实时指标、仓位风险摘要和最近事件。原区间选择、资产走势、持仓/现货、筛选与排序继续使用原组件。
- 今日净盈亏使用 Hyperliquid 官方盈亏曲线，以 UTC+8 零点切分。保留零点附近插值的「估算」标记。今日已实现单独汇总当日合约成交的 `closedPnl` 字段，与官方区间净盈亏分开显示。现货、手续费和资金费的精细核算放在阶段二。
- 前端优先使用现有全市场仓位 WebSocket。断线后复用默认市场 REST 降级。总仓位和保证金按当前可读取的仓位求和，并标明范围。风险等级采用最短有效强平距离（不超过 5% 为高风险、不超过 15% 为需关注），该等级描述看板所见的强平风险。过期或不完整的数据不能得出低风险结论。
- 新增同源只读 `GET /api/overview-activity?wallet=...`。它复用现有鉴权、Hyperliquid 预算和并发合并，按已验证的公开地址读取近 24 小时成交与非资金费流水。今日合约已实现仅在成交覆盖可核对时显示。最近事件包含开仓、平仓、反手、入金、出金和当前账户保存的风险提醒。
- 行情缓存只保存公开钱包数据，提醒按登录账户与钱包查询。无新增表、迁移、定时任务或推送规则。前端以较仓位更新更低的频率查询最近事件。
- 验收包括旧测试、今日边界和资金不计入收益、截断去重、跨账户读数、WebSocket 断线降级和手机布局。独立 Git 分支先供审核。

## 阶段二　账户流水与收益核算

- 统一采集服务维护按市场、钱包和数据源划分的覆盖范围与游标。官方 WebSocket 用于实时成交、资金费和流水事件，REST 用于启动、重连重扫、分页补历史。统一执行按权重限流、退避和延迟记录。
- 新增只写入归集的数据表，例如 `market_fills`、`funding_entries`、`ledger_entries`、`equity_snapshots`、`sync_cursors`。唯一键包含钱包和官方事件身份。合并账户和市场维度，记录原币种、精确数字和来源；披露截断、缺口与覆盖区间。共享公开数据时，账户只通过已保存钱包关联访问个人设置和权益快照。
- 在现有盈亏页增加独立流水和收益核算视图。充值、提现和内部转账单列。核对 `closedPnl`、手续费、Builder 费用和资金费的官方字段语义与符号，避免在净交易收益中重复扣费。回填与资产快照由后台任务独立维护并设预算。
- 使用新增表和索引的增量迁移，先保持旧路径可读。回滚通过停用新采集任务和界面、运行上一版可兼容代码，保留已写入的数据供恢复。需要恢复旧库时使用部署前备份；生产回滚不得覆盖升级后产生的账户、钱包或提醒，应先核对并导出增量。

## 阶段三　风险预警

- 新增保证金使用率、单仓亏损或收益率、账户每日净亏损与回撤、仓位数量突变和 API 中断规则。继续复用当前强平距离、账户阈值和通知策略。
- 在现有提醒页提供三级风险状态、冷却设置与锁屏隐私选项。扩充提醒元数据为时间、币种、具体阈值、等级、来源和钱包/仓位定位。接近强平的高风险继续优先发送。
- 每条规则以账户、钱包、仓位、规则、级别和触发周期组成幂等键，状态和待推送消息在同一事务提交。继续使用设备发送记录和稳定 Web Push 标签去重。数据断流使用带迟滞的恢复/恶化状态避免反复告警。

## 阶段四　历史交易与验证

- 在现有动态和盈亏入口扩展成交记录、未成交订单及状态历史。后台同步官方用户订单与成交，保留事件身份与重放游标，仅提供只读查看。
- 从成交重建仓位生命周期和加减仓，单列手续费、Builder 费用及资金费。完整开平仓在证据足够时再计算单笔收益和日、周、月统计。历史不足仍展示可核实区间。
- 每阶段运行权限、幂等、数据覆盖、回填和断线测试。iPhone 布局以窄屏及触控浏览器测试，PWA 安装和锁屏通知另做真机审核。迁移全部先用数据库副本验收，生产部署留待人工确认。

## v1.4.0 部署与运行范围

- SQLite 0003 和 0004 增加公开钱包记录、同步区间、权益样本、挂单快照及账户内提醒详情。应用可回滚到上一版本，旧版会忽略新增表。恢复数据库备份前需考虑快照之后的写入。
- 成交、资金费和流水先同步近期数据，再逐步补到最近 32 天。交易所的成交保留上限及历史订单范围适用。历史订单接口只补回返回的状态，部署前的中间状态有可能缺失。
- 实时连接订阅有数量限制，超出时使用后台 REST 轮询。历史账本按保存钱包轮询。所有记录列表显示确认区间或样本时间，定时扫描与实时推送使用同一套账户隔离和通知去重。
- 单仓净收益在成交和资金费覆盖完整、费用可归集且结算币种一致时可用。按交易所官方盈亏曲线计算的今日净亏损，沿用 UTC+8 的零点样本规则。
